# Sharing a YouTube video

Build 184 already had the OFFLINEShareExtension target. The Phase 0 device test established Share-sheet registration and receipt of a URL. Phase 8 connects that extension to the existing Import Link sheet. In YouTube or Safari, share the video, choose Muzik Belesh, check its address, tap **Save Link**, then **Done**. Open Muzik Belesh and tap **Inspect Link**. Video Details retains its quality picker and Download Audio button.

## Host input

The existing extension target loads a UIKit view controller. Activation accepts text, one web URL or one Safari webpage. Safari preprocessing returns only the page address through the system property-list key. The extension does not read page content. XcodeGen generates these keys from project.yml. The checked-in Info.plist reflects the same rules.

SharedURLHandler walks at most eight extension items and twelve providers with one eight-second deadline. It reads URL objects, strings, attributed item text, and the specific Safari result dictionary. It ignores local file references and does not read arbitrary files or decode arbitrary attachment bytes. Text can contain a title and whitespace-separated links. Repeated representations of one video are accepted. Conflicting IDs, unrelated external URLs, unreadable supported providers, and oversized inputs fail. Dismissal cancels the outstanding read and late callbacks are ignored.

Both processes use YouTubeURLValidator. The extension requires a trusted HTTPS URL, strips tracking by storing the validated 11-character ID, and displays the reconstructed watch URL. Manual entry in the app also accepts a bare valid ID. Sharing performs no network request.

## Handoff and recovery

Both targets request `group.com.th07.muzikbelesh.inbox`. A single bounded JSON file holds the schema version and at most 16 pending records with event UUID, video ID and creation time. Membership indicates pending delivery. NSFileCoordinator serializes the read/modify/write operation across processes, and each mutation replaces the file atomically. The reader limits the file to 8 KiB, checks its type, schema, event IDs and every video ID. Unknown or corrupt files produce an error and are preserved. Full queues reject new videos. A repeat of a pending video coalesces. Old accepted events have no time-based expiry.

On active cold launch or foreground return the app reads the oldest event, waits for current modal work to finish, then presents the existing Import Link sheet with its canonical URL. Appearance of the prefilled sheet acknowledges delivery. Cancelling a displayed sheet dismisses that delivered item. The next pending item can then appear. A crash before acknowledgement permits redelivery. A failed acknowledgement is retried on reconciliation. Repeated acknowledgement by UUID is safe. Each manual import opens a fresh empty field. Inspection and downloading require separate user actions. The extension has no dependency on the app database, download session, playback engine, or YouTubeKit.

## Apple and SideStore

Apple supports sharing an App Group container between separately sandboxed processes. File coordination provides the transaction boundary that shared UserDefaults alone would lack. Completing the request returns control to the host. The extension point decides whether NSExtensionContext.open is supported. Apple's documented iOS opening options omit Share. UIApplication.shared is unavailable to extensions. URL schemes, Universal Links and SwiftUI onOpenURL can route an opening event that another authorized caller initiated. They cannot confer foreground-launch permission on Share, so Phase 8 registers no route. Automatic app opening is **BLOCKED**. [Extension lifecycle](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/ExtensionOverview.html) · [NSExtensionContext.open](https://developer.apple.com/documentation/foundation/nsextensioncontext/open(_:completionhandler:)) · [Shared containers and Safari preprocessing](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/ExtensionScenarios.html) · [Coordinating shared files](https://developer.apple.com/library/archive/technotes/tn2408/_index.html)

The canonical bundle IDs remain com.th07.muzikbelesh and com.th07.muzikbelesh.share. The IPA has no Apple identity or device provisioning profile. Its two executables carry ad-hoc signatures containing the requested group so SideStore can discover it. The packager extracts both entitlement dictionaries and compares them with the source plist. SideStore reads executable entitlements, requests groups for each App ID, and may append the signing team ID. Source configuration and this packaging check cannot establish what the installed signer grants. [SideStore provisioning implementation](https://github.com/SideStore/SideStore/blob/cd260851ae99bf1fc946b123db24e89c8cd21dc6/SideStore/Core/Operations/PipelineOperations/FetchProvisioningProfilesOperation.swift) · [SideStore executable entitlement reader](https://github.com/SideStore/AltSign/blob/master/AltSign/Model/ALTApplication.mm)

Each process tries the product's group, including a narrowly matched team-suffixed form from signing metadata or the installed containing app ID. FileManager enforces access for each lookup. The extension reports success only after storage succeeds. Settings → Diagnostics reports whether the app can read the inbox. Saving an event and seeing that same video in the app is the cross-process probe. Custom bundle IDs or different group rewriting may require diagnosis against the actual signed package. No device-signed Phase 8 profiles or physical results were available during implementation.

## Verification and rollback

ShareURLValidationTests exercise normalization, trust boundaries, real NSItemProvider representations, errors, deadlines and cancellation. SharedLinkInboxTests use isolated on-disk queues for replay, bounded concurrent access, invalid schemas and storage errors. YouTubeUITests seeds a debug-only isolated inbox and follows inspection, fixture download and playback. CI also runs the existing download, library and compact-device regressions. The PR records run IDs, outcomes and the package hash. Actual host providers, signing, and in-place upgrade require the [iPhone acceptance matrix](PHASE_08_DEVICE_TESTING.md).

The handoff adds no migration to the music database or changes to private music storage. To withdraw the feature, revert the sharing change and produce a higher-numbered build using the same application identity. Pending shared links live separately. Preserve the installed app container during re-signing and testing.
