# Muzik Belesh — Build, CI and publication pipeline

This document describes the **v1.2.0** build and release pipeline. For the user-facing app, see [README](../README.md). For installation, see [SideStore instructions](SIDELOADING.md).

## Current toolchain

The GitHub Actions workflows use GitHub-hosted **`macos-15`** runners and a pinned **Xcode 26.2** installation. The project is generated by **XcodeGen 2.46.0** from `project.yml`.

The project is a native iOS 17+ app. The main executable target is `OFFLINE`, and the Share extension target is `OFFLINEShareExtension`.

Current package versions for the accepted v1.2.0 build:

| Dependency | Resolved release |
| --- | --- |
| GRDB | 7.11.1 |
| YouTubeKit | 0.4.10 |
| ZIPFoundation | 0.9.20 |

The workflow and packaging manifest are the source of truth for the resolved revisions. These packages should not be upgraded without compatibility/regression checks.

## Main workflows

| Workflow | Path | Purpose |
| --- | --- | --- |
| CI | `.github/workflows/ci.yml` | Static checks and deterministic unit/integration/UI regression shards |
| Build unsigned IPA | `.github/workflows/build-ipa.yml` | Builds Release arm64 app and extension, then packages and validates an unsigned IPA |
| Playlist migration verification | `.github/workflows/playlist-migration.yml` | Targeted migration test coverage |
| Publish v1.2.0 | `.github/workflows/publish-v1.2.0.yml` | Manually authorizes, checks and publishes the exact physically accepted IPA |
| Historical v1.1.0 publisher | `.github/workflows/publish-v1.1.0.yml` | Retained unchanged for historical provenance |

The CI workflow contains selectable diagnostic scopes. Static test hygiene is checked with `Scripts/check-test-hygiene.py`, and test results are verified from `.xcresult` by `Scripts/check-test-results.py`.

A successful build does **not** establish that every test passed. Skipped, canceled, timed-out or not-run tests must not be reported as successful.

## Building locally on macOS

```bash
git clone https://github.com/T-h07/MuzikBelesh.git
cd MuzikBelesh
git switch develop

xcodegen generate
xcodebuild -resolvePackageDependencies \
  -project OFFLINE.xcodeproj -scheme OFFLINE

xcodebuild -project OFFLINE.xcodeproj -scheme OFFLINE \
  -configuration Debug \
  -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO build
```

Native iOS compilation, XCTest and iPhone simulator execution require an appropriate macOS/Xcode environment. Windows can be used for editing and Git, but is not a substitute for Xcode testing.

## Unsigned IPA creation

`build-ipa.yml` builds with the device SDK and disables normal code signing:

```bash
xcodebuild -project OFFLINE.xcodeproj -scheme OFFLINE \
  -configuration Release -sdk iphoneos \
  -destination 'generic/platform=iOS' \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO \
  CODE_SIGN_IDENTITY="" build
```

The workflow accepts an optional positive `build_number`; use a number **higher than already distributed builds**. The accepted v1.2.0 candidate explicitly used build **200**.

`Scripts/package-ipa.sh` creates `Payload/OFFLINE.app` and packages `OFFLINE-unsigned.ipa`. It verifies:

- ARM64 executables for the app and the Share extension.
- Matching marketing version and build numbers, with the marketing version sourced from `project.yml`.
- Main app and Share extension bundle identifiers, `MinimumOSVersion` and extension configuration.
- App assets, launch screen, background-audio support and `.mbelesh` document declarations.
- Expected App Group metadata on both executables.
- Absence of unexpected provisioning/signing material and test-only device-binary markers.
- ZIP structure, source-commit provenance and final archive integrity.

The packaging script adds **ad-hoc entitlement metadata** so SideStore can request the App Group for both executables. It does **not** ship an Apple signing identity; the IPA still needs SideStore re-signing before installation.

The Actions artifact `OFFLINE-unsigned-IPA` contains:

- `OFFLINE-unsigned.ipa`
- `OFFLINE-build-manifest.json`
- `OFFLINE-unsigned.ipa.sha256`

The JSON manifest records source SHA, embedded short commit, app/extension identity, version/build, minimum OS, resolved packages and the SHA-256 computed from the final IPA bytes.

## Manual publication protection

The v1.2.0 publisher:

1. Runs **manually** on `main` with an explicit approval input.
2. Is pinned to an accepted artifact run ID, build number, source SHA and SHA-256.
3. Confirms the app source, resources, extension and packaging inputs are unchanged since acceptance.
4. Downloads the accepted IPA instead of building an untested replacement.
5. Checks the IPA bytes, both embedded bundles, manifest and version/build numbers.
6. Creates the version tag and GitHub Release without moving an existing tag.
7. Downloads the published IPA again to confirm its checksum.

**The v1.2.0 release has already been published.** Do not rerun its publication with different executable bytes or overwrite the historical artifacts.

## Test reliability and runner limitations

GitHub-hosted macOS runners can be queued or unavailable. Runner allocation problems are not evidence that code compiled, passed or failed. A known failing regression is still a failure until root-caused or reverified.

The v1.2.0 expedited release intentionally proceeded after successful packaging and 10/10 reported physical smoke checks; final full CI and migration verification were canceled, and earlier failures remain in the documented release-risk register. Future bug fixes should run their relevant deterministic and device tests rather than inheriting that exception.
